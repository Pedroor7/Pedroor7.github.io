How I work with a team

  1. Map the process

    I sit with the people doing the work and find where the time actually goes, before touching any tool.

  2. Build the smallest useful version

    Something real people use in days, not a demo. Usually n8n plus an LLM, and a small app when the process needs one.

  3. Test against real cases

    Real conversations and real statements become the test set, so every change can be checked before it ships.

  4. Run it and stay close

    Monitoring, fixes and iteration after launch. The job isn’t done until the team stops doing it by hand.
